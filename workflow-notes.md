## Workflow relationships

### Issue

The Issue describes what needs to be completed and provides criteria that can be checked before the work is merged.

### Feature branch

The `feature/github-ai-workflow` branch separates the assignment work from `main`. This allows the documentation to be developed and reviewed without changing the default branch immediately.

### Commits

Commits create identifiable snapshots of related changes. Each commit uses a descriptive message so its purpose can be understood from the repository history.

### Pull request

The pull request will compare `feature/github-ai-workflow` with `main`. It will connect the completed changes to Issue #1 and provide a place for review, discussion, and verification.

### Review and merge

A review or self-review comment will identify a strength and an improvement, question, or clarification. After the acceptance criteria are satisfied, the pull request will be merged into `main`.

### Default branch

The `main` branch represents the completed version of the assignment. It will contain `README.md`, `workflow-notes.md`, and `ai-log.md` after the pull request is merged.
